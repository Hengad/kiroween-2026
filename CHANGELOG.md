# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).
Entries are prefixed with their scope: `core:`, `factory:`, `festival:`, `repo:` or `kiro:`.

## [Unreleased]

### Added

- kiro: Steering files for product vision, engine architecture and domain language, tech stack, repository structure, TDD workflow, project memory, and file-scoped conventions for Python, Svelte and simulations.
- kiro: Hooks that remind the agent to write tests first and to update README and CHANGELOG when a spec task completes.
- repo: README, CHANGELOG, MIT license and `.gitignore` (`.kiro/` stays committed, as the hackathon rules require).
- kiro: Decided that README.md and CHANGELOG.md are pulled into every Kiro task through `project-memory.md` file references, so earlier decisions are always in context.
- kiro: Decided on deterministic Detectors and Rules by default, with an optional LLM `Reasoner` behind an interface, so demos and tests run offline.
- kiro: Decided that simulations act as external Sources and feed the engine only through connectors, so they can be swapped for real systems.

### Changed

- kiro: Reframed the engine as a set of optional, configurable **components** (features) rather than something extended only by plugins. The three pillars are goals, not components; components are concrete features introduced over time. Updated `product.md`, `architecture.md` and `README.md`. Customization is now "configuration first, then extension points," with plugins as an optional way to bundle custom code. The concrete component list is deliberately left open.
- repo: Restructured the demo apps to share the core backend. Apps are no longer "backend/simulation/frontend" triplets; instead they are "config/simulation/frontend" with a `main.py` that starts the shared core backend. Each app defines which components to enable and their configuration in `config.yaml`, optionally providing custom code through the Plugin mechanism. Updated `structure.md`, `README.md` and the repository layout.
- kiro: Manual editing and refinement of the files by Henry. Aligning the text more into my vision of the engine / code template.
- kiro: Defined the first four components in `product.md`: Ask, Question and request tracking, Change monitoring, and Process builder (Svelte Flow). Recorded the demo layout (simulation left, engine right; Chat and Tracked questions views) and the decisions on hackathon scope.
- kiro: Replaced Rules and Insights with Processes and incidents in `architecture.md`. Processes are user-built node graphs stored as configuration; incidents are Work Items. Added terms for Answer Outcome, Acceptance, Conflict Resolution, Claim, Response Window and Citation.
- kiro: Changed the "single owner" invariant to "at most one owner, never forgotten", because tracked questions start unowned and are auto-assigned only after their response window expires. Added the `awaiting_acceptance` status for answers the asker has not yet accepted.
- kiro: Updated `frontend.md`, `structure.md`, `tech.md`, `tdd.md`, `simulations.md` and `README.md` to match. Added `@xyflow/svelte` to the stack.
- repo: Workspace scaffold. uv workspace with the `siloless` backend package (FastAPI app factory `create_app` with `/health`, pytest, Hypothesis, ruff, strict mypy) and an npm workspace with the `@siloless/ui` Svelte 5 package (Vitest, Testing Library, svelte-check, a `ConnectionStatus` component). Both started from a failing test.
- kiro: The `tdd-guard` hook is now a command hook (`.kiro/hooks/tdd-guard.ps1`). It reminds the agent to have a failing test first only for production code, and stays silent for docs, `.kiro/`, config and test files. The old agent hook fired on every doc edit.
- repo: `npm audit` reports 2 low-severity findings (`deepmerge` via `@sveltejs/vite-plugin-svelte`). Dev tooling only and no fix is available, so they are left as is.
- kiro: Drafted `.kiro/specs/memory-and-work-foundation/requirements.md` (spec 1 of the build plan): Principals, Record ingestion and versioning, permission-filtered reads and search, Entities and Relations, Event Log, Work Items with lifecycle and claims, and the HTTP API. Not yet approved; design and tasks follow after review.
- kiro: Wrote `.kiro/specs/memory-and-work-foundation/design.md`. Chose synchronous storage services over async SQLAlchemy, a single shared SQL read filter for all permission checks, and compare-and-set `UPDATE`s for claims and transitions so exactly one concurrent claim wins. Work Item events store the changed fields, so replaying the log rebuilds current state. Added `access/` and `storage/` modules to the architecture.
- kiro: Fixed two permission flaws found while designing. Derived objects (Relations, Work Items) are now readable by anyone who can read every Record version they derive from, replacing the "intersection of ACLs" wording, which fails when different groups overlap in membership. An older Record version is now also hidden when access to the current version is revoked.
- kiro: Wrote `.kiro/specs/memory-and-work-foundation/tasks.md` (17 test-first tasks). Settled design decisions D1 to D5, and amended `backend.md`: storage and domain services are synchronous, with async reserved for WebSockets and connectors.
- core: Spec 1 tasks 1 to 7 (`memory-and-work-foundation`). Added the clock, ULID ids, errors and settings; principals, group membership and the ACL rule; the SQLite storage layer (write transactions start with `BEGIN IMMEDIATE`, FTS5 search index, append-only event log enforced by triggers); the event log; idempotent versioned Record ingestion; authoritative-Record rules; and permission-filtered Record reads. A Record keeps every version, `list_versions` returns them newest first with the latest marked current, and a Source tightening access hides older versions too. Two Hypothesis property tests check reads against an independent oracle; deliberately breaking the filter makes them fail.
- core: Full-text search over the current version of every readable Record (spec 1 task 8). User text is split into quoted words so it can never act as FTS5 syntax, and the permission filter sits in the same statement as the match. A property test checks that results equal exactly what each user may read.
- core: First slice of the HTTP API: principals and memberships, `POST /ingest/records`, Record and version reads, and search, with problem-details errors and stable error codes. The `X-Principal-Id` header is declared as an OpenAPI security scheme so the `/docs` page can send it, so it is now a constant and the `principal_header` setting is removed. `create_app` now takes `Settings`.
- core: Finished spec 1 (`memory-and-work-foundation`, tasks 9 to 17). Entities and Relations with a type registry, idempotent upserts, referential integrity enforced by foreign keys, and readability that follows the Records they connect. Work Items with a strict seven-state lifecycle, one-winner claims implemented as a single conditional `UPDATE`, reassignment, resolution text, and a history that replays to the current state. The rest of the HTTP API (entities, relations, work items, events), an Alembic baseline that matches `install_schema` exactly, `.env.example`, and `ProblemDetails` in the OpenAPI description.
- core: Tests that guard the invariants: a stateful Hypothesis machine for the Work Item lifecycle, single-owner and append-only-history properties, a relation integrity property, and a real 8-thread claim race (20 rounds) on a file database. Deliberately breaking the claim condition fails five of them, as does breaking the permission filter.
- kiro: Deviations from the design are recorded at the end of `design.md` (no retry on lost races, evidence order, creator-readable evidence, extra error codes).
- core: Added `uvicorn` to the backend dependencies. The documented run command failed with "Failed to spawn: uvicorn" because it was never declared, and the earlier checks ran the app in-process.
